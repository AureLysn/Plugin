# `git-guard` — Safe Git Operations & PreToolUse Guards

General-purpose Git safety plugin for **all repositories** on Aurel's workstation (the vault root `D:\AureLysn`, a repository since 2026-11-12, the two app repositories in `01_Origine/03_Systems/`: `Atelier`, `AureLysnOS`, and the two zone repositories `05_Evasion/` and `04_Portfolio/`, the latter holding the website code in `Portfolio_Web/`). Its skills work in any Git repository; `nhanh-va-commit` and `git-cuu-ho` name vault paths (`01_Origine/04_Tools/VaultTool/…`, `01_Origine/05_Meta/Index/vault-index.json`) only in the steps that apply when the repository is the vault.

---

## 1. Skills (`4` Skills)

| Skill | Purpose |
|---|---|
| `git-an-toan` | Pre-flight Git inspection, `.git/index.lock` checks, line-ending protection, worktree placement outside the main tree, and destructive-command prohibitions |
| `nhanh-va-commit` | Branch naming (`loai/mo-ta-ngan`), explicit file staging (never `git add -A`), pre-commit gate execution when `CLAUDE.md` + `01_Origine/` exist, and `git diff --stat` line-ending verification |
| `pr-va-merge` | For all five repositories, once at the close of a session (Aurel, 2026-11-14). Pushing feature branches, opening GitHub PRs via `gh`, inspecting CI checks, and merging safely without mutating the main working tree |
| `git-cuu-ho` | Recovering from mid-session Git faults: stale `index.lock`, wrong-branch commits, CRLF/LF full-file diffs, merge conflicts, and `git reflog` recovery |

## 2. `PreToolUse` Safety Hooks (`8` Hooks, `2` Shared Modules, `11` Test Suites)

Every hook intercepts `Bash` and `PowerShell` tool calls (`run_command` on Antigravity) before execution; `chan_sua_rao_chan.py` also intercepts `Write`, `Edit`, `MultiEdit` and `NotebookEdit` on Claude Code (`exit 0` = allow, `exit 2` = block with explanation on `stderr`). `PowerShell` joined the matcher on 2026-11-23: it is the primary shell on this workstation, and before that a `git checkout <branch>` or `git mv` typed there reached no hook. Every hook fails open (`exit 0`) on unreadable input (not JSON, no `tool_input`, a command that is not text) and reports an internal error as a non-blocking `exit 1`.

**Strict mode (0.8.0, `[[plugin-benchmark-20261124]]` G4).** With `GIT_GUARD_STRICT=1` in the environment, every hook blocks unreadable input and failed checks (`exit 2`, reason on `stderr`) instead of letting them through; readable commands are judged exactly as before. It is off by default: turning it on is Aurel's decision, made by adding `"env": {"GIT_GUARD_STRICT": "1"}` to `~/.claude/settings.json` (all projects) or to the repository's `.claude/settings.json`. Tests: `hooks/test_che_do_chat.py`.

**Reading commands (0.8.0).** `hooks/tach_lenh.py` reads a command as its shell does (Bash, PowerShell or cmd, by the tool that runs it) and gives every hook the same simple form: comments dropped, continued lines joined, heredoc bodies removed, and every quoted string and PowerShell here-string inert, so that the text of a commit message is never taken for a command. Each hook then checks that form and each form unwrapped from it: `bash`/`sh -c` and here-strings, `powershell`/`pwsh -Command`, `-EncodedCommand` and a positional script, `cmd /c` (`cmd //c`) and `/k`, `Invoke-Expression`, `eval`, `Start-Process`, `{ script blocks }`, `( … )` and `@( … )`, the bodies of one-line `if … then` / `for … do`, launcher prefixes (`&`, `env`, `time`, `nohup`, `exec`, `sudo`, `xargs`, `timeout`, `wsl`, `uv run`, `VAR=value`), a quoted or path-qualified `git.exe`, `$( … )` and backtick bodies, and heredocs fed to a shell. A block wins over an ask. Until 0.8.0 these forms reached no hook (`[[plugin-benchmark-20261124]]` N1), and comments, here-strings with an apostrophe and multi-line messages were read as commands (N7). Payloads are read as UTF-8 bytes; Python would decode them with the console code page (cp1252 here). Still not unwrapped: `python -c` / `node -e` bodies, commands built from variables (`& $git reset`), `find … -exec` and what `xargs` reads, `case` branches, `trap`, `cmd /s /c` quoting, scripts run from files. If `tach_lenh.py` cannot be imported, each hook checks the raw command only. Tests: `hooks/test_tach_lenh.py`; 27,000 fuzzed commands gave no crash and no unbalanced quote (executed 2026-11-24).

It follows `cd` and variables assigned earlier in the same command, into `if { }` bodies, loops and subshells too; a target it cannot resolve counts as risky when the delete is recursive or runs in the vault (a `cd` to an unknown folder counts as where the command started). | `hooks/chan_sua_rao_chan.py` | `hooks/test_chan_sua_rao_chan.py` | Asks Aurel before the session changes its own guardrails (0.8.0, `[[plugin-benchmark-20261124]]` G6): `CLAUDE.md`, every `hooks.json`, `.claude/settings.json` / `.claude/settings.local.json`, `managed-settings.json`, `~/.claude.json`, `.claude-plugin/plugin.json` / `marketplace.json`, anything under `~/.claude/plugins/` or a `.claude/hooks/` folder, and the hook rules of the vault (`01_Origine/05_Meta/Rules/hook/`, V2) — through `Write`/`Edit`/`MultiEdit`/`NotebookEdit`, or a shell command that writes the file (`>`, `tee`, `Set-Content`, `cp`, `mv`, `rm`, …). `hooks/duong_dan.py` holds the path handling that the last two hooks, the nested-checkout check and the rule engine of `vault-ops` (its own identical copy) share: one form for Git Bash, PowerShell and cmd paths, `cd` / `pushd` / `popd` and variable tracking, the files a command writes, the protected roots, scratch, temp and cache folders, and `walk`, which yields every simple command of a command with its program, words, shell and the scope it runs in (tests: `hooks/test_duong_dan.py`). Replaying 932 real tool calls of three sessions through the eight hooks on 2026-11-24 gave 15 decisions and no false one (executed; `[[plugin-benchmark-20261124]]` N6). Each hook runs in its own Python process (about 60–70 ms each on this workstation, executed 2026-11-24).

## Two hook configs, one per agent host

- `hooks/hooks.json` uses `${CLAUDE_PLUGIN_ROOT}` paths and is the config Claude Code loads.
- `hooks.json` at the plugin root uses relative `python hooks/<name>.py` commands and serves Google Antigravity (Aurel, 2026-11-13).
- The hook scripts in `hooks/` are the single source; both configs must list the same scripts. Change both in the same edit. Since 0.8.0 the Claude Code config also has a `Write|Edit|MultiEdit|NotebookEdit` matcher for `chan_sua_rao_chan.py`.
- Save both configs as UTF-8 **without BOM**. Claude Code rejects a `hooks.json` that starts with a BOM (`JSON Parse error: Unrecognized token`) and loads none of the plugin's hooks; the BOM sat in both plugins from 2026-11-14 until 2026-11-23 (`claude plugin list` showed `failed to load`).
